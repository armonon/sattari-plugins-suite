# Auto Pitch Live Mode and sample-rate x buffer matrix, 2026-09-27

Tool: `AutoPitchLiveMatrix` (`plugins/auto-pitch/tools/auto_pitch_live_matrix.cpp`), R&D branch
`rnd/next-gen-20260927`, base commit `e94d5e7`. The plugin DSP sources (`plugins/auto-pitch/src`,
`core/`) are identical to `a87e261`, so these numbers describe that DSP. Release build (arm64,
Rubber Band print engine, ONNX on, Neural Pitch off). Machine: Apple M4 (4P + 6E cores), shared
with other work (Logic Pro open, load average 3-6) during the runs.

Machine-readable results: `2026-09-27-e94d5e7.json` (72 configurations, every raw number, the gate
constants and the verdicts) and `2026-09-27-e94d5e7-real-vocal.json` (real-vocal timing pass).

## Method

Each configuration is a fresh processor, default stereo layout (mono material on both channels),
`prepareToPlay` at the rate and maximum block, then fixed-size blocks, with the processor's
AsyncUpdater drained between blocks as a host's message thread would (same host emulation as
`AutoPitchNoHarm`).

- Modes: Studio; Live Extreme 2MS (`liveMode`, `liveProfile` Ultra, `extremeLive` on); Live Ultra
  Quality C3+ (`extremeLive` off); Live Extended Range (`liveProfile` 1).
- Matrix: SR {44.1, 48, 88.2, 96} kHz x block {32, 64, 128, 256} (Studio also 512, 1024).
- Latency: `getLatencySamples()` vs measured delay, in the output timeline:
  - single-sample clicks on silence (0.5 FS, 8 clicks, argmax of the centred second difference);
  - the same clicks riding a corrected, voiced B3 +45 c sine (the shifter is engaged);
  - a synthetic vocal (the NoHarm VocalGen: vibrato C4, glide, 20-note detuned C-major melody)
    with 4 ms noise "consonant" bursts at every note start: per-burst arrival, high-pass (second
    difference) cross-correlation, and 2 ms amplitude-envelope cross-correlation;
  - real vocals: 6 vocadito dev clips (1, 2, 11, 12, 13, 37; CC BY 4.0; never the sealed holdout)
    at 44.1/48/96 kHz, block 128, `--vocal`. The plain whole-waveform cross-correlation is kept in
    the JSON but not used: on strongly periodic, pitch-shifted material it locks onto a neighbouring
    pitch period (it swung between -60 and +97 ms here).
- CPU: thread CPU time (`CLOCK_THREAD_CPUTIME_ID`, immune to preemption) and wall time for every
  block, on one thread at QoS user-interactive, after 1.5 s of warm-up, 3 trials x 6 s of the
  synthetic vocal (Natural, 100 %, speed 0.9, C major); the verdict uses the median over trials of
  p99 and of max. Back-to-back blocks with hot caches: a best case for the plugin.
- Accuracy (Classic style, 100 %, speed 1, C chromatic, Sound Source Wide): steady B3 +45 c (target
  B3); E2 +30 c (Ultra: C3 +30 c, its documented floor); C5 -30 c; a 5.5 Hz +-40 c vibrato on A3;
  semitone (A3 -> A#3) and fifth (A3 -> E4) steps. Pitch is a 10 %-trimmed mean of a 4-period
  zero-crossing track (robust to a single spurious crossing from a splice). Settling = time from the
  input step until the output stays within +-10 c of the new note (includes latency).
- Artifacts: NaN/Inf, peak, zero runs >= 1 ms inside continuous tones, and discontinuities as
  "step level": the largest second difference relative to the output peak, in dB. A step
  discontinuity of size s shows as a second difference of about s, so -20 dB is a jump of 10 % of
  the note's amplitude; a clean sine sits at 20 log10((2 pi f / sr)^2), at most -45 dB here. Unlike
  a ratio to the ideal curvature, this does not grow with the sample rate. Plus a 12-change note
  train (semitones to fifths, up and down, 0.25 s notes): per change, the step level in the 130 ms
  after it; a change "clicks" at >= -20 dB.
- Buffer dependence: output at each block vs block 32 at the same SR (vocal and B3 tone).

## Gates

The matrix verdict covers the configuration; the artifact verdict covers the engine. A row passes
only if both pass.

| Gate | Threshold | Why |
|---|---|---|
| CPU p99 | <= 70 % of the block budget | The host, the driver and every other plugin share the same callback. The tail causes dropouts, so the gate is p99, not the mean. At 70 % one instance leaves under a third of the callback for everything else. |
| CPU max | <= 100 % (median over 3 trials) | A single block over budget is a guaranteed dropout even with nothing else loaded. Median over trials rejects one-off OS events. |
| Instances @p99 | reported: floor(budget / p99) | How many instances fit serially on one core in the worst 1 % of blocks. |
| Latency (Live) | clicks on silence within 0.25 ms of reported; vocal high-pass xcorr within 0.5 ms | Live claims exact agreement on the fixed-delay path. |
| Latency (all) | reported latency constant during playback | Host PDC. |
| Studio transient offset | note only | Documented Rubber Band characteristic (2026-09-25 release readiness). |
| B3 +45 c | <= 5 c | The no-harm fixture (AutoPitchNoHarm check 5). |
| E2 / C3 / C5 | <= 10 c | Near the pitch-discrimination limit for sustained tones. The 08-31 Extreme record measured 6.04 c max. |
| Vibrato | p95 of the output track within 50 c of A3 | The input never exceeds 40 c, so anything wider means the correction adds vibrato or flips notes. |
| Settling | <= 300 ms, and <= the 48 kHz reference + max(20 ms, 50 %) | The reference is block 128 for Live and 512 for Studio. A configuration must not retune audibly slower than the qualified reference. |
| Dropouts | no zero run >= 1 ms in continuous tones | |
| Discontinuities | tone or vocal step level < -20 dB; no note change >= -20 dB | A 10 % jump is an audible click on a sustained note. The verdicts are not sensitive to the exact value: Extreme sits at +3 to +6 dB, and Ultra/Range clicks reach -4 dB. |

## Findings

1. **Live Extreme clicks on every pitch movement, at every SR and buffer.** 11-12 of 12 note changes
   produce waveform jumps up to +6 dB re peak, i.e. full-scale. On the synthetic vocal the step
   level is +3 to +6 dB. On real vocals it is 13-30 dB above the input's own level on the 4 of 6 clips
   whose input has no discontinuity of its own. During vibrato
   there is a splice every pitch period (about 200 per second, about -20 dB). Steady tones are clean
   (-46 to -78 dB), which is why the 2026-08-31 steady-tone and THD qualification did not see this.
   - Cause: `core/include/sattari_audio_core/SattariLivePitchEngine.h:772-777`. The smoothstep
     crossfade blends the old and new cycle at the same offset, and only for phase 0-0.2. The wrap
     from offset ~`smoothedPeriod` back to 0 is continuous only when `smoothedPeriod` equals the
     true period.
   - `smoothedPeriod` is updated once per host block with a 0.45 exponent and a 0.8-1.25 clamp
     (`:725-730`), so it lags whenever the pitch moves. The lag also depends on block size.
2. **Extreme is 2.00 ms only on its dry/unvoiced path.**
   - Clicks on silence and the vocal high-pass correlation agree exactly (0.00 ms).
   - Voiced content comes out later: clicks on a corrected tone +3.9 to +5.6 ms, consonant bursts
     inside the vocal +2.8 to +3.7 ms, synthetic-vocal envelope +1.3 to +4.3 ms, and real vocals up
     to +11.2 ms (vocadito 13).
   - Cause: `findCycleStart` reads the newest complete cycle, which ends `minimumDelay` plus one
     period behind the write head (`SattariLivePitchEngine.h:824-825`). Resynthesised voiced audio
     is therefore about one pitch period older than the dry path.
3. **Ultra Quality C3+ and Extended Range fail the artifact gate in 30 of 32 cells.**
   - In 29 cells, 1-7 of 12 note changes click at >= -20 dB (worst -4 dB). Ultra 88.2 k/256 fails
     on a -11 dB step in the fifth.
   - The two passing cells (Ultra 48 k/128 and 44.1 k/256) still have 5 of 12 changes at >= -30 dB.
   - Whether a given change clicks depends on the splice phase, so no cell can be called click-free.
   - Clicks are worse at 88.2/96 k: Range clicks at 2-7 of 12 changes, with tone steps up to -6 dB.
   - Engine: `LiveEpochShifter` (`SattariLivePitchEngine.h:250`).
   - Everything else in the Live matrix is clean: latency is exact at every SR (Ultra 11.90 ms at
     44.1/48 k, 11.81/11.80 at 88.2/96 k; Range 21.6/21.5 ms), accuracy is within 0.2 c, and there
     are no dropouts or NaN.
4. **"Extreme is outside the budget at 96 kHz / 64" is refuted.**
   - Measured at 96 k/64: p99 40 %, max 51 %, 2 instances. Only 96 k/32 fails (p99 80 %).
   - The old claim came from a policy label, not a measurement: `plugins/auto-pitch/tools/auto_pitch_bench.cpp:727`
     passes `qualified = sr <= 48000`, and `:688-690` prints "OUTSIDE" without applying a gate.
   - Ultra and Range pass CPU at every rate and buffer, 32 included (worst: Range 96 k/32, p99 62 %).
5. **"96 kHz at <= 128 samples fails the CPU budget" is confirmed for Studio, and the failure is wider.**
   - Studio's mean load is low (11-18 % at 44.1/48 k), but a few heavy blocks cost 2-2.5 ms of CPU
     at 48 k whatever the buffer size.
   - Studio fails at 48 k <= 128 (48 k/128 is borderline: max 101 %, and 93-104 % across the runs made while developing the tool),
     at 44.1 k <= 64, and at 88.2/96 k <= 256.
   - At 88.2/96 k Studio averages 33-48 % of a core: only 1-2 instances fit even at 512/1024.
6. **Studio at 44.1 kHz widens vibrato, at every buffer.**
   - The output vibrato p95 is 55-70 c against an input of +-40 c; at 48 k it is 14-23 c, and at
     88.2/96 k 25-35 c.
   - At 48 k the 5.5 Hz residual is 19 c at -61 deg. At 44.1 k it is 34 c at -100 deg, plus a 19 c
     rms non-sinusoidal error.
   - The cause is not isolated. The reported latency is the same 2885 samples at 44.1 and 48 k
     (65.4 vs 60.1 ms), and the pitch hop is a fixed 256 samples.
7. **Studio real-vocal timing does not reproduce the 2026-09-25 record.**
   - The record said "whole real vocals within ~1 ms". On all 6 vocadito dev clips the envelope
     correlation lands +6.5 to +7.8 ms after the reported delay at 44.1/48 k, and +11 to +15 ms at
     96 k. The high-pass correlation agrees on 4-5 of 6 clips per rate (+7.1 to +8.6 ms at 44.1/48 k).
   - Clicks on silence depend on the block size: at 48 k they arrive +9.2 ms late at block 32 but
     0.77 ms early at 512/1024.
8. **Live settling grows with the buffer.**
   - Extreme semitone step: 28 ms at 48 k/128, 39 ms at 256, 54 ms at 44.1 k/256 (fails the
     relative gate).
   - Ultra fifth step: 81 ms at 44.1 k/256 (fails).
   - The causal planner updates once per host block.
9. **No mode is buffer-size invariant.**
   - The vocal output differs from the block-32 render by -5 to -14 dBFS (waveform level, i.e.
     correction timing and phase). The steady B3 tone differs by -9 to -24 dB for Studio/Extreme and
     -29 to -40 dB for Ultra/Range.
   - This is reported only, not gated.

```sh
HOME=/tmp/rnd-home cmake -S plugins/auto-pitch -B build/auto-pitch-rnd -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_OSX_ARCHITECTURES=arm64 -DSATTARI_AUTOPITCH_PRINT_ENGINE=RUBBERBAND -DSATTARI_USE_ONNX=ON \
  -DONNXRUNTIME_INCLUDE_DIR=$PWD/third_party/onnxruntime-osx-universal2-1.22.0/include \
  -DONNXRUNTIME_LIB=$PWD/third_party/onnxruntime-osx-universal2-1.22.0/lib/libonnxruntime.dylib
HOME=/tmp/rnd-home ninja -C build/auto-pitch-rnd AutoPitchLiveMatrix
B=build/auto-pitch-rnd/AutoPitchLiveMatrix
$B --mode studio --sr 44100 --sr 48000 --out f/studio_44_48.json      # ~5 min
$B --mode studio --sr 88200 --out f/studio_88.json                    # ~3 min
$B --mode studio --sr 96000 --out f/studio_96.json                    # ~3 min
for m in extreme ultra range; do $B --mode $m --out f/$m.json; done   # ~2 min each
$B --merge out.json out.md f/*.json
# real-vocal timing pass (no CPU):
$B --sr 44100 --sr 48000 --sr 96000 --block 128 --cpu-seconds 0 --vocal ~/datasets/vocadito/Audio/vocadito_1.wav --out fv/v1.json
```

`--dump-dir DIR` writes every render as a WAV (output, input). The renders are deterministic, and
only the CPU columns vary from run to run.
